Rosetta manufacturing documentation defines what must exist before a PCB order is treated as a controlled release.

## Important: drill data is missing

No `.drl`, Excellon or other drill file is present in the reviewed archive.

This is a manufacturing blocker for any design that includes plated through-holes, vias or non-plated holes. The Gerber copper layers can show annular pads, but they do not tell the fabricator the drill tool diameters and drill coordinates required to manufacture those holes.

Therefore this archive should be marked:

> **INCOMPLETE FABRICATION PACKAGE — DO NOT RELEASE FOR PRODUCTION WITHOUT DRILL DATA AND FINAL REVIEW.**

## Required fabrication package

A complete Rosetta PCB fabrication release should contain at least:

### Gerber layers

F.Cu.

B.Cu.

F.Mask.

B.Mask.

F.Silkscreen.

B.Silkscreen.

Edge.Cuts.

Paste layers are required when creating stencils or assembly data.

### Drill files

Export the correct plated/non-plated drill data from KiCad. If separate PTH and NPTH files are generated, both must be included.

### Job / metadata

Keep the `.gbrjob` file because it records layer functions and board metadata.

## Assembly package

If an assembler will place components, also provide final BOM; component position / pick-and-place file; assembly drawing where useful; polarity/orientation notes; DNP list; and approved substitutions.

Gerbers alone are not a PCBA package.

## Outline review

The Edge.Cuts file contains multiple closed paths around the circular main outline/top feature. The manufacturer preview must be inspected to make sure the intended outer perimeter is recognized correctly.

Do not rely only on the filename `Edge_Cuts.gbr`; visually confirm the rendered board profile.

## Pre-order checklist

Before uploading to a board house, confirm the following: schematic revision frozen; PCB revision frozen; DRC reviewed; footprints manually checked; Edge.Cuts visually verified; Gerbers regenerated from the frozen PCB; plated drill file included; non-plated drill file included where applicable; board dimensions verified; manufacturer Gerber preview inspected; copper polarity/layer mapping correct; silkscreen orientation and polarity marks checked; surface finish selected; BOM matches schematic; placement file matches PCB revision; and release archive renamed with an explicit revision.

## Versioning

A future fabrication ZIP should use a release-style filename, for example:

```text
rosetta-v2.0-fab-2026-09-08.zip
```

The ZIP should never be edited manually after export. If something changes, regenerate it and issue a new release identifier.

## First article

The first manufactured Rosetta v2 board should be treated as a **first article**, not automatically as a production unit. It should pass the electrical and functional procedure in [Assembly & Bring-up](assembly-and-bring-up.md) before a larger batch is approved.
