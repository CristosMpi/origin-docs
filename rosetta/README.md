# Rosetta

**Rosetta** is the custom electronics platform at the center of ORIGIN Core. It concentrates the project’s embedded processing, power-management, local interfaces, storage and sensor connectivity onto a purpose-built PCB so that ORIGIN can move beyond a collection of development boards and temporary wiring.

Rosetta is documented separately from the rest of ORIGIN Core because it is both a subsystem and a product-development effort of its own. Changes to the board affect power, firmware, enclosure geometry, sensor wiring, manufacturability and serviceability.

## Current generation

The current documented generation is **Rosetta v2**.

The latest manufacturing export reviewed for these docs is named `Rosetta_V2_Reviewed (1)` and was generated by **KiCad Pcbnew 10.0.1** on **18 July 2026**. Its Gerber job file describes a two-layer FR-4 board with an overall exported size of **100.05 × 104.8 mm** and a nominal board thickness of **1.6 mm**.

Those values describe the uploaded manufacturing export. They do not by themselves prove that the export is complete or ready to order. The reviewed ZIP is missing drill data, which is documented under [Manufacturing](manufacturing.md).

## What Rosetta is responsible for

At system level, Rosetta provides the electrical foundation for:

- embedded processing;
- battery and input-power handling;
- regulated power rails;
- sensor and expansion interfaces;
- local storage;
- communications interfaces;
- status and control signals;
- connection between ORIGIN Core and the wider software stack.

A useful abstraction is:

```text
Power source
    ↓
Power management
    ↓
Rosetta regulated rails
    ↓
Embedded processor
    ├── Sensors
    ├── Storage
    ├── Communications
    ├── Expansion interfaces
    └── Diagnostics / status
```

## Design goals

Rosetta v2 is intended to improve several areas compared with breadboard-style prototypes:

### Integration

The board places the main embedded electronics into one repeatable hardware platform.

### Reliability

Fixed traces, connectors and footprints reduce the number of loose wires and ad-hoc interconnections that can fail during transport or field use.

### Serviceability

A documented PCB can be inspected, reproduced, revised and replaced more systematically than a one-off prototype.

### Manufacturability

The design is prepared around standard PCB fabrication and assembly workflows, including Gerber copper, mask, paste, silkscreen and profile layers.

### Iteration

Rosetta is versioned. Design issues should be recorded and corrected in later revisions rather than hidden inside undocumented modifications.

## Documentation status

The Rosetta chapter distinguishes three kinds of information:

1. **Verified from the uploaded manufacturing export** — dimensions, layer count, stack-up metadata and included Gerber layers.
2. **Confirmed from the project design history** — major functional blocks and components used during Rosetta v2 development.
3. **Still requiring source-file verification** — exact pin maps, final component quantities, reference designators, final drill data and production-ready BOM information.

This distinction matters because a Gerber archive can verify physical manufacturing layers, but it cannot replace the schematic, PCB source, BOM and assembly files.
